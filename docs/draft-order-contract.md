# Provisional editable draft order contract

Roadmap milestone 3 uses the catalog's prototype-derived menu and integer MXN cents. No backend order endpoint is specified or called.

`src/features/order/types.ts` defines the local draft and its lines. Each add creates a distinct line ID, even for the same product. A line stores the product ID, selected option IDs, quantity, note, and the catalog product snapshot used to price it. `src/features/order/rules.ts` validates configurations against the current catalog, copies selections, and calculates line and order totals with safe integer arithmetic. Editing a line keeps its ID. Decrementing a line from quantity one to zero removes it. Negative, fractional, and unsafe quantities are rejected. The customer name is kept as entered, while confirmation eligibility uses its trimmed value.

`useDraftOrder(catalog)` owns React state on the sale screen. Its `addLine`, `updateLine`, `setLineQuantity`, `removeLine`, and `setCustomerName` methods update derived totals immediately and return success/failure. Errors appear as `mutationError` rather than being thrown during a React state update. `canConfirm` is true only when the draft has at least one line, a nonblank customer name, and no menu mismatch. If a refreshed catalog removes a product, invalidates its selection, or changes its price, the saved snapshot keeps the line visible with its original total while `draftIssue` explains why the confirmation gate is blocked. Editing against the current menu or removing affected lines resolves it. This milestone only exposes the gate; confirmation, comanda creation, cancellation, and payment belong to later milestones.

The draft is **memory-only**. It is discarded when the sale screen unmounts or the page reloads. `resetDraft` clears it explicitly. There is no browser storage, backend persistence, shared-register synchronization, or recovery after navigation/reload. Catalog product availability and prices are provisional and may change; a future order service needs a confirmed price snapshot and stale-catalog policy before committing an order.
